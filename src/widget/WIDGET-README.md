# AI Assistant review widget — NexServe (service desk)

Rollout plan Fase 4. The floating review assistant (Ask / Findings / Readiness /
Jejak saya) shared with accreditation and academy. It is **additive**: the in-app
"AI Assist" on Home (`parseAIQuery`, natural-language → prefilled request form) is
untouched — that is the product feature; this widget is the reviewer tool.

## Layout
- `core/` — framework-agnostic store / collector / engine / identity / registry /
  guidance / vanilla shell + widget.css. **Synced verbatim from accreditation**
  (`ops/prototypes/sync-widget.sh service-desk`); never hand-edit here.
- `app.config.js` — NexServe's own `PROJECT_ID='nexserve'`,
  `FEEDBACK_APP='servicedesk'`, `CHECK_AREAS` (9 review areas), `QUICK_PROMPTS`,
  `SCREEN_LABELS`, `AREA_GUIDE`. This app exports `CHECK_AREAS` here and the React
  shell injects them into `createStore` (core keeps its generic default).
- `contextAdapter.js` — builds the passive host context (config summary only).
- `knowledge.js` — manual answer rules + `SOURCES` (win over generated).
- `knowledge.generated.js` — AUTO-GENERATED by `scripts/gen-knowledge.mjs` from
  `src/ServiceDesk.jsx`; do not hand-edit. Run `npm run gen:knowledge`.
- `ReadinessWidget.jsx` / `index.js` — the React shell + public entry.

## Mount
`ServiceDesk.jsx` renders `<ReadinessWidget project="nexserve" .../>` in both the
login and main returns (reachable from first access). `collectorEnabled` is true
only behind the `/servicedesk/` deployment (`COLLECTOR_ENABLED`), so off-deployment
events queue locally but are never POSTed (no browser-logged fetch error).

## Tests (TDD)
`npm run test:widget` → core smokes + `knowledge.smoke.mjs` (in-scope battery →
100% ANSWERED_FROM_SOURCE, out-of-scope → CLARIFICATION_NEEDED) +
`guidance.smoke.mjs` (every area real, every route a real screen, every prompt
answered).
